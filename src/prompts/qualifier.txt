Field notes:

- `prepare` is the list of argv that must run before any test can run at all
  (code generation, a build the tests import, an environment fix). Order
  matters. It may be empty only if the tests genuinely run on a bare checkout.
- `verify` is the ordered list of argv the harness runs. Exactly ONE of them —
  the one named by `suite_index` — is the suite, and its output must carry the
  authoritative total. Any other entry is a supporting check.
- `expect_at_base` is `"exit0"` for anything that is expected to be GREEN on a
  clean checkout at the pinned base. Use `"red"` ONLY for a command that is
  supposed to fail there (an operator-supplied oracle that is red before the
  fix). A `"red"` entry that exits 0 is treated as vacuous and fails the pass.
- `suite_runner` picks the PARSER, never a command: `tap` needs exactly one
  `# tests N` line on stdout with N > 0; `pytest` needs exactly one summary
  line ending in `in X.XXs` carrying `N passed`. If the repo's own runner
  emits neither, that is what `runner_gap` and `adapter` are for.
- `collection_probe`, when you can supply one, is an object
  `{"target": "path/to/the/file", "snippet": "the text appended to it"}` — a
  snippet appended to one file that makes exactly one test fail. It is how the
  pass proves the suite count is live rather than cached. Leave it `null`
  rather than guessing a snippet that will not compile.
- `traps` is prose for a human. Nothing is gated on it. Put the things that
  would cost someone a debugging cycle here.
