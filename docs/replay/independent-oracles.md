# Independent oracles (reliability rung)

Read when the result set must support the RELIABILITY claim: authoring holdouts from the issue spec alone, blinding and sealing the scribe, base-only materialization, and the scoring rules for independent vs expert oracles.

Purpose: upgrade the claim from "reproduces known-good under the expert's tests" to "satisfies an independently-authored spec" — `references/claim-ladder.md`'s reliability rung (§8a) requires these on a subset.

- Author the holdout test from the TRUNCATED ISSUE SPEC ALONE (the post-truncation body, `references/oracle-and-issue.md` §6), author BLINDED to the gold patch — never open the gold diff or the expert test patch during authoring. Phrase assertions from the issue's behavioral claims, not the fix's shape. WHY: any peek makes the oracle expert-test-derived and the rung claim collapses.
- Artifact separation: independent holdouts are separate files from the path-rewritten expert tests (e.g. `holdout_indep_<n>.py` vs `holdout_<n>.py`); both may run in the same exec scenario or separate ones, but they are NEVER merged into one artifact.
- Validation identical to the holdout contract (`references/oracle-and-issue.md` §5): RED at base, GREEN at gold, marker, `expected_exit: 0`. An independent oracle that does not flip red→green at the gold patch is INVALIDATED — the issue spec was underspecified; record it as such, never salvage by reading the gold patch.
- Scoring: score docs count independent vs expert oracles per instance, separately. An instance with both is double-weighted evidence (expert-typical behavior + independently-specified behavior). Divergences between the two oracles are findings, not noise — they mark issue-spec underspecification, a real product defect class the factory will meet in the wild.
- Scribe isolation is STRUCTURAL, not behavioral: seal the scribe's materials in a clean dir (spec + BASE_NOTE copies ONLY — never the instance dir, which may hold gold-derived artifacts); give the scribe absolute paths to exactly those two files. WHY: a prompt ban on opening poisoned files held only by discipline; a stray glob/cat in the same dir collapses the blinding.
- Base code for the scribe is materialized BASE-ONLY: `git init` + `git fetch --depth 1 origin <base-sha>` + `git checkout FETCH_HEAD` (the clone-ref rule in `references/setup.md`, applied to authoring) — verify the merge sha is UNREACHABLE in the clone before authoring begins. WHY: a full clone puts the fix in the object DB, one git command from the blinded author.
- BASE_NOTE clone paths must be persistent, never /tmp of a prior session (batch-2's notes went stale and the scribe had to re-derive); if the path is missing, re-materialize base-only per the rule above rather than full-cloning.
- Scribe assertions may use ONLY APIs verified present in the base checkout (grep/import-check the base code, never recall from memory). WHY: batch-2's pyasn1-82 oracle died at gold on a hallucinated `sameAs()` call — RED-at-base cannot catch it when the base failure surfaces earlier in the call chain than the bad assertion.
